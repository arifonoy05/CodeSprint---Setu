# RCA-1078 — Blacklisted borrower disbursed

**Severity:** High
**Module:** Loan Disbursement
**Raised:** 2024-11-04
**Closed:** 2024-11-12

## Summary
A borrower blacklisted by Compliance two days before disbursement received funds.

## What happened
The blacklist flag was set on the borrower record after loan approval. `checkEligibility()` does run
at disbursement time and does read `is_blacklisted`, so the check itself worked — but the bulk
disbursement batch calls `createDisbursementTxn()` directly and never calls `checkEligibility()`.

## Root cause
Two callers, one gate. The officer screen goes through `disburse()`, which checks eligibility. The
bulk batch bypasses it. The eligibility gate is enforced at the caller, not at the point where money
actually moves.

## Preventive action
**Open.** The gate belongs where every path converges, not on one path.
