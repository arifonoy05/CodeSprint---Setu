# RCA-1041 — Duplicate disbursement on client retry

**Severity:** Critical
**Module:** Loan Disbursement
**Raised:** 2024-03-14
**Closed:** 2024-03-21

## Summary
A single approved loan was disbursed twice, producing two ledger postings totalling twice the
sanctioned principal. Detected by treasury reconciliation the following morning, not by the system.

## What happened
The officer's browser timed out waiting for the core banking gateway, which was running slow. The
officer clicked Disburse again. Both requests completed successfully at the gateway.

## Root cause
`disburse()` creates a `disbursement_txn` row and posts to the ledger with no idempotency key, and
`disbursement_txn` has no unique constraint that would prevent a second successful disbursement for
the same loan. There is no request de-duplication at any layer.

## Resolution
Manual reversal raised with Finance. A unique partial index was discussed but not implemented,
because tranche-based products legitimately create multiple rows per loan.

## Preventive action
**Open.** Requires an idempotency key supplied by the caller. Not yet scheduled.
